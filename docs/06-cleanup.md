# Lab 6 - Clean up and identify production changes

**Goal:** remove workshop costs and persistent access. **Time:** 10 minutes.

## 1. Stop delivery before removing infrastructure

Confirm the repository and Azure context are your **disposable workshop** scope.
Capture non-sensitive evidence first. Disable publish and close obsolete release
PRs so an approved run cannot recreate a proposal during cleanup:

```powershell
gh variable set WORKSHOP_PUBLISH_ENABLED --body false --repo $GitHubRepo
gh workflow disable publish.yml --repo $GitHubRepo
```

Cancel any queued/running publish job in Actions. Stop port-forwards and watch
commands with Ctrl+C. Do not delete a shared cluster or shared resource group.

## 2. Remove GitHub access

With the administrator, remove the workshop repository's read-only deploy key,
delete `RELEASE_APP_PRIVATE_KEY`, and uninstall the release App from this
repository. Delete the App itself only if it was created exclusively for this
lab. Remove the workshop variables and `dev` environment if no longer needed.
Retain/ archive the repository according to organizational policy.

Remove locally downloaded App PEM/key files from their specific locations after
checking you no longer need them. For the deploy key generated by the guide:

```powershell
Remove-Item .local\argocd_repo, .local\argocd_repo.pub
```

Never recursively remove a home, workspace, or shared key directory.

## 3. Delete the isolated Azure resource group

Review the active subscription, resource group name, tags, and resources:

```powershell
az account show --query "{Name:name,State:state}" -o table
az resource list --resource-group $ResourceGroup --query "[].{Name:name,Type:type}" -o table
```

Only after confirming the group contains **exclusively workshop resources**, run:

```powershell
az group delete --name $ResourceGroup
```

Read and answer the Azure CLI confirmation yourself. This permanently removes
AKS, ACR images, and the workshop managed identity/federated credential. AKS
removal also removes its managed node resources; verify completion rather than
assuming the asynchronous deletion finished:

```powershell
az group exists --name $ResourceGroup
```

Wait until this returns `false` and check the Azure portal for any remaining lab
node resource group. If an administrator supplied shared infrastructure, have
them remove only the workshop Application, workloads, credentials, and role
assignments; do not run the resource-group deletion command.

## 4. Discuss what must change for production

| Lab simplification | Production decision |
| --- | --- |
| One repository and dev overlay | App/platform separation, multiple environments, artifact promotion without rebuild |
| Free tier, fixed nodes | Evaluate AKS Automatic, SLOs, zones, topology spread, PDBs, autoscaling and cost |
| Administrator bootstrap and broad controller installation | Restricted Argo RBAC, SSO, platform ownership, audited bootstrap |
| Registry-scoped Contributor for build identity | Verified least-privilege ACR task/build and repository permissions |
| Major action tags and floating container base | Full action SHA pins, reviewed base digest and patch automation |
| Container smoke tests and rendered YAML | Admission/policy tests, image scanning, SBOM, provenance, signature verification |
| Public restricted API; localhost access | Private control plane, egress design, approved runners, Gateway API, DNS and trusted TLS |
| Read-only local deploy key | Secret manager, rotation and approved GitHub App authentication |
| Basic probes and logs | Metrics/traces, alerts, deployment analysis and release SLOs |
| Human release PR approval | Environment-specific promotion policy, separation of duties and auditable exceptions |

Do not describe the sample as production-ready or promise zero downtime. The
learning objective is a complete, reviewable agent-to-GitOps delivery loop.

**Checkpoint:** no workshop resources accruing costs and no unneeded App, deploy
key, or federated access remains.
